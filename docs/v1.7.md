## search_node：节点日志（2026-10-23）

本次只为搜索节点增加观测记录，不改变其他节点和图的停止路由。

- 每次执行在 `finally` 输出一条 JSON 日志，包含 `run_id`、`task_id`、
  `node_name`、`round`、开始时间、耗时、状态、错误及产出摘要。
- `round` 是本次搜索轮次，取状态中已完成轮数加一。
- `output_summary` 记录本轮派发查询数、成功/失败查询数、新增来源数和累计来源数。
  派发查询数不等于已经完成的查询数；取消或处理中断时，摘要可能不完整。
- `query_errors` 记录失败查询及异常类型、信息，不记录完整搜索响应。

| 状态 | 日志级别 | 含义 |
| --- | --- | --- |
| `succeeded` | INFO | 所有查询正常返回；结果为空也算调用成功 |
| `partial_success` | WARNING | 部分查询失败，仍保留成功查询的来源 |
| `failed` | ERROR | 全部查询失败，或节点处理发生未预期异常 |
| `skipped` | INFO | 没有待查询问题，或搜索预算已耗尽，原因写入摘要 |
| `cancelled` | INFO | 节点或内部查询被取消，取消继续向上传播 |

日志状态描述本次搜索结果，不直接控制图的路由：全部查询失败时，沿用原有策略返回
`error_calls`，由后续 `update_node` 判断停止；未预期的处理异常则记录后重新抛出。

当前计数口径保持不变：`search_calls` 累计成功的工具调用，失败另计入 `error_calls`；
没有待查询问题时仍按原逻辑增加一次 `error_calls`。搜索工具可能命中缓存，所以不能
把这些计数解释为实际远程 API 请求数或费用。本次不增加 token、价格或缓存命中字段。

验证：`python -m unittest discover -s tests -v`，11 项离线测试通过。覆盖成功、空结果、
部分/全部失败、预算跳过与截断、无查询、来源去重、输入状态不被修改、异常传播、
外部/内部取消，以及 LangGraph 注入运行配置。模拟模型和搜索客户端，不消耗 API 额度。
尚未进行真实搜索接口或完整研究流程的联调。

## web_search_tool：缓存与远程调用日志（2026-10-23）

每次工具执行输出一条 JSON 日志。`search_node` 通过复制运行配置中的 metadata，
把任务 ID 和轮次传给工具；保留原有 thread_id、回调和标签，不修改共享配置。
日志中的 `run_id`、`task_id`、`round` 可与节点记录关联，`query` 用于区分并行查询。
单独调用工具、未提供运行上下文时，对应关联字段为 null，不伪造 ID。

| 字段 | 含义 |
| --- | --- |
| `tool_name` | 固定为 `web_search_tool` |
| `cache_status` | `hit` 命中、`miss` 未命中；读取失败时为 `unknown` |
| `cache_namespace` | 搜索参数对应的缓存命名空间，例如 `basic-5-1500` |
| `duration_ms` | 整个工具执行耗时，包括缓存读取、远程搜索、整理结果及缓存写入 |
| `remote_requested` | 是否进入 `client.search` 调用，不等于供应商收到请求或实际计费 |
| `remote_duration_ms` | SDK 调用耗时，异常或取消也记录；未调用时为 null |
| `result_count` | 缓存或标准化响应中的结果数量，尚未经过节点来源去重；未知时为 null |
| `error` | 异常阶段、类型和信息；正常完成时为 null |

状态使用 `succeeded`、`failed`、`cancelled`，失败输出 ERROR，其余输出 INFO。
缓存未命中本身不算错误：联网搜索并成功写入缓存后，状态仍然是 succeeded。
错误阶段分为 `cache_read`、`offline_check`、`remote_search`、`normalize`、`cache_write`；
取消时用 `cancelled_stage` 标出阶段，并继续向上传播。

沿用现有缓存失败策略：缓存损坏、写入失败仍然抛异常，没有增加自动重试或降级。
因此远程搜索成功但缓存写入失败时，日志可以同时出现 result_count > 0 和 failed。
本次不记录完整搜索响应、API key、价格或 token 用量。

验证：`python -m unittest discover -s tests -v`，累计 25 项离线测试通过。
新增覆盖真实临时缓存的首次未命中与再次命中、参数隔离、离线模式、缓存损坏、
远程异常、响应整理异常、缓存写入失败、取消，以及并行任务上下文隔离。
未调用真实搜索 API；真实供应商延迟和费用尚未测量。
